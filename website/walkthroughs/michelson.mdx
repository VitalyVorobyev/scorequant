# Phase Estimation in a Michelson Interferometer

*A fringe pattern is read out through $K$ bins. The phase is to be estimated while the fringe frequency is a nuisance. Which detector positions should each bin collect?*

## 1. The interferometer

A [Michelson interferometer](https://en.wikipedia.org/wiki/Michelson_interferometer) splits a coherent beam into two arms and recombines the reflected beams on a detector. A slight tilt between the returning wavefronts makes their relative phase vary across the detector, so the intensity forms bright and dark bands, the fringes. A change in the optical path difference shifts the phase and moves the pattern sideways; measuring that shift is the purpose of the instrument.

/>

A real detector varies in illumination, efficiency and background across its surface. A readout through a few bins needs a few calibrated quantities instead of a model of every pixel. The choice of bins then decides how much information about the phase survives.

## 2. The model and its score

The detector coordinate $u$ is scaled so that one fringe has length $2\pi$; the detector spans {f("fringes")} fringes, $u\in[0,8\pi)$. A detected photon lands at $u$ with density

$$
p(u\mid\varphi,\epsilon)
\propto
1+V\cos\!\bigl((1+\epsilon)u+\varphi\bigr),
$$

with visibility $V={}${f("visibility")}. The phase $\varphi$ is the parameter of interest. The small fractional frequency error $\epsilon$ stretches the pattern across the detector, so an unknown $\epsilon$ can partly imitate a phase shift.

ScoreQuant works with the score, the gradient of the log density with respect to the parameters. At the reference point $(\varphi,\epsilon)=(0,0)$,

$$
s_\varphi(u)
=
-\frac{V\sin u}{1+V\cos u},
\qquad
s_\epsilon(u)
=
u\,s_\varphi(u)-V.
$$

The phase score is largest on the slopes of a fringe, where a small shift changes the intensity most, and has opposite signs on the rising and the falling slope.

The score enters ScoreQuant as a function of the observation:

```python
import numpy as np
import scorequant as sq

EXECUTION = sq.ExecutionConfig(backend="numpy", precision="float64", device="cpu")

VISIBILITY = 0.60
N_FRINGES = 4
U_MAX = 2.0 * np.pi * N_FRINGES

SCHEMA = sq.ScoreSchema(("phase", "fringe_frequency"))
INTEREST = SCHEMA.select("phase")


def fringe_density(observations):
    u = np.asarray(observations)[:, 0]
    return (1.0 + VISIBILITY * np.cos(u)) / U_MAX


def michelson_score(observations):
    u = np.asarray(observations)[:, 0]
    s_phase = -VISIBILITY * np.sin(u) / (1.0 + VISIBILITY * np.cos(u))
    return np.column_stack([s_phase, u * s_phase - VISIBILITY])


provider = sq.ScoreFunction(
    michelson_score,
    provenance=sq.ScoreProvenance(kind="exact", reference_point=(0.0, 0.0)),
    schema=SCHEMA,
)
```

## 3. Why equal segments fail

The obvious readout cuts the detector into equal segments. A bin responds to the phase through the mean phase score of the positions it collects, so a segment spanning both slopes of a fringe adds contributions of opposite sign, and they largely cancel. With one segment per fringe they cancel exactly: the integral of a cosine over a full period does not depend on its phase, so the counts carry no information about $\varphi$ at all.

<FringeCurve
  segments={factValue("michelson", "fringes")}

/>

The reason is simple: the information is carried by the score, not by the position. Distant positions with the same score can share a bin; neighbours on opposite slopes must not.

## 4. Binning in score space

The score maps each detector position to a point $s(u)=\bigl(s_\varphi(u),\,s_\epsilon(u)\bigr)$. The image is a curve with one loop per fringe, each longer than the last because the frequency score grows with $u$.

<Figure
  src={siteUrl("figures/michelson-score-space.svg")}
  alt="The Michelson model in score space: the phase score on the horizontal axis against the fringe-frequency score on the vertical, drawn as four narrow loops from a common point near the origin, each longer than the last."
  caption={<>The detector mapped into score space. Each point of the curve is one position <Tex>{"u"}</Tex>.</>}
  paper
/>

A partition into $K$ cells with probability masses $W_b$ and mean scores $\mu_b$ retains the Fisher information

$$
I_{\mathrm{bin}}
=
\sum_{b=1}^{K} W_b\,\mu_b\mu_b^\top .
$$

A cell enters only through its mass and its mean score, so it should collect positions with similar scores: the cells belong in score space. When both parameters matter, the standard criterion is D-optimality, $\max_q \log\det I_{\mathrm{bin}}$, which values retained information in every direction at once.

The optimization works on a fine grid of detector nodes, each carrying the probability of its interval:

```python
N_NODES = 8_000
step = U_MAX / N_NODES

u = (np.arange(N_NODES) + 0.5) * step
observations = u[:, None]
weights = fringe_density(observations) * step
scores = provider.score(observations, execution=EXECUTION)
```

## 5. The D-optimal partition

`optimize_partition` assigns the nodes to $K$ cells by exact exchange: a node changes cell whenever that increases the determinant, until no single move does.

```python
N_BINS = 6

d_partition = sq.optimize_partition(
    scores,
    weights=weights,
    n_bins=N_BINS,
    criterion=sq.DOptimality(),
    config=sq.DExchangeConfig(seed=4),
    execution=EXECUTION,
)

d_quantizer = d_partition.compile_quantizer(execution=EXECUTION)
new_scores = provider.score(np.array([[1.0], [7.0], [15.0]]), execution=EXECUTION)
new_bins_d = d_quantizer.predict_scores(new_scores, execution=EXECUTION)
```

In an exchange-stable D-optimal partition with a nonsingular Fisher matrix, every node is strictly nearest the mean score of its own cell in the metric of the inverse binned Fisher matrix: the partition is a Mahalanobis–Voronoi partition of score space (<ReferenceLink to="guide/#the-one-crossing-compiling-a-partition">user guide</ReferenceLink>). The {f("bins")} cells are therefore connected regions with straight boundaries. Along the detector, however, they form a comb, because the score curve passes through each cell several times.

The theorem also supplies a rule. The optimization labels only the grid nodes, but the Voronoi geometry assigns a bin to any score vector, so `compile_quantizer` turns the partition into a reusable readout $u \to s(u) \to q\bigl(s(u)\bigr)$.

## 6. Reporting the phase alone

Usually only $\varphi$ is reported, and $\epsilon$ is estimated beside it because it can imitate a phase shift: the two scores are strongly correlated, {f("correlation")} at the reference point. The information about $\varphi$ that survives estimating $\epsilon$ from the same data is the profiled phase information

$$
I_{\varphi\mid\epsilon}
=
I_{\varphi\varphi}
-
\frac{I_{\varphi\epsilon}^2}{I_{\epsilon\epsilon}}.
$$

D-optimality spends cells on resolving $\epsilon$ as carefully as $\varphi$; the profiled criterion $D_s$ maximizes $\log I_{\varphi\mid\epsilon}^{\mathrm{bin}}$ instead. A partition is judged by the fraction of the unbinned profiled information it retains. For one parameter of interest ScoreQuant also computes a certified upper bound on that fraction for any $K$-bin partition (<ReferenceLink to="api/#the-efficient-score-upper-bound">API guide</ReferenceLink>), and its partition is the starting point of the exchange:

```python
bound = sq.efficient_score_bound(
    scores, interest=INTEREST, weights=weights, n_bins=N_BINS, execution=EXECUTION
)

ds_partition = sq.optimize_partition(
    scores,
    weights=weights,
    n_bins=N_BINS,
    criterion=sq.ProfiledDOptimality(interest=INTEREST),
    config=sq.DExchangeConfig(seed=4),
    initial_labels=bound.labels,
    execution=EXECUTION,
)
```

## 7. A reusable rule for the phase

  paper
  wide
/>

Profiling changes the shape of the solution. The D cells separate the loops from one another, which is what resolving $\epsilon$ requires. The profiled cells cut across the loops: they separate values of the efficient score $\hat s = s_\varphi - (I_{\varphi\epsilon}/I_{\epsilon\epsilon})\,s_\epsilon$, the part of the phase sensitivity that the nuisance cannot reproduce. Intervals of this scalar, mapped back through the oscillating detector coordinate, give the fragmented comb at the bottom.

Unlike the D case, a finite profiled partition does not in general define a Voronoi rule; even a global optimum can violate the nearest-cell geometry of its own metric, so `compile_quantizer` refuses it (<ReferenceLink to="guide/#parameters-of-interest-with-nuisance">user guide</ReferenceLink>). A reusable profiled readout is fitted directly with `fit_quantizer`, from the continuous detector density and the same score; `SoftVoronoiConfig` fits a smooth score-space rule and hardens it into $K$ bins.

```python
source = sq.IntegrationSource(
    [[0.0, U_MAX]],
    density=fringe_density,
    quadrature=sq.GaussLegendreConfig(order=256),
)

ds_quantizer = sq.fit_quantizer(
    source,
    provider=provider,
    n_bins=N_BINS,
    criterion=sq.ProfiledDOptimality(interest=INTEREST),
    config=sq.SoftVoronoiConfig(seed=4, initializer_restarts=8, max_steps=1000),
    execution=EXECUTION,
)

new_bins_ds = ds_quantizer.predict_scores(new_scores, execution=EXECUTION)
```

The fitted rule retains {f("dsRuleProfiledRetention")} of the profiled phase information, against {f("profiledRetentionAtSix")} for the finite partition, and its detector comb is simpler. The loss against the finite partition is the price of a rule that classifies new observations.

## 8. What the result means

Equal detector segments lose phase information because the score changes sign within every fringe. Bins drawn in score space keep positions with similar scores together, wherever they lie on the detector. When both parameters matter, the D-optimal bins form a Voronoi diagram in score space and compile into a reusable rule. When only the phase is reported, the profiled criterion keeps as much phase information as any partition of the same size can.

The example also separates two tasks: `optimize_partition` labels a fixed weighted table, and `fit_quantizer` returns a rule for new observations. For D-optimality the first compiles into the second; for the profiled criterion the rule must be fitted, and it keeps somewhat less. Both tasks are described in the <ReferenceLink to="guide/">user guide</ReferenceLink>.
